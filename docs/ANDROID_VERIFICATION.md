## Remaining field checks and limits

The calendar reports `ro.build.type=userdebug` and `ro.debuggable=1`. Its Chrome 83 WebView keeps the app inspectable over authorized ADB despite the release flag and explicit `setWebContentsDebuggingEnabled(false)`. Chromium's matching [SharedStatics source](https://github.com/chromium/chromium/blob/83.0.4103.120/android_webview/glue/java/src/com/android/webview/chromium/SharedStatics.java) explicitly ignores this API on debug Android builds. An initial socket check ran before the engine finished starting; the delayed check and real inspection endpoint corrected that result. No device restrictions or firmware settings were changed. AND-06 remains open for this hardening criterion; a supported production WebView/firmware or a future native UI needs separate validation. The installed release is usable, but do not describe WebView inspection as disabled on this calendar.

The actual calendar microphone picked up weak/ambient audio during one test and Whisper produced an unreliable transcript. The editable review step prevented submission. Quiet audio is now rejected before inference. Clean-file accuracy does not establish accuracy for conversational speech at a distance or in noise; multilingual and far-field usage still need testing with the user speaking to the calendar. This build makes no speech-quality score claim.

A normal Mac app launch while the Mac was locked previously waited while opening a project checklist. The user subsequently allowed the file-access prompts; a normal unlocked LaunchServices restart now loads projects and answers a real calendar question. The initial consent check has passed. The Android UI retains cached data and advises checking Mac file-access prompts if initial loading stalls. Locked startup, later login and sleep/wake still need field validation.

Physical Mac sleep/wake, router roaming/address changes, long unattended operation and power-cycle recovery have not been forced during this coding session. Transport loss/restart, expiry, revocation and uncertain delivery have automated coverage; server shutdown has on-device coverage. Re-pair when the Mac address or certificate changes. No device restrictions, root access, calendar removal, launcher replacement or away-from-home endpoint were introduced.
